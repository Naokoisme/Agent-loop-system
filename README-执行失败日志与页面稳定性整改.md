# 执行失败日志与页面稳定性整改说明

> 日期：2026-08-25
> 范围：测试历史、单用例/批次异常归档、日志下载、顶部导航稳定性

## 改了什么

- 新运行记录在原有 `run.json`、截图之外，新增：
  - `stdout.log`：执行器标准输出。
  - `stderr.log`：执行器错误输出。
  - `events.jsonl`：开始、命令、阶段错误、截图和结束事件。
- 测试历史详情新增“原始执行日志”，执行异常时自动展开；支持下载全部日志、错误日志和阶段事件。
- 旧历史仍从 `run.json` 读取和下载日志，不要求迁移已有记录。
- 单用例在预检失败、初始化异常、取消或未捕获异常时，也会生成正式失败历史。
- 批次在当前用例准备或编排阶段异常时，为该用例生成兜底历史，并通过批次令牌避免重复归档。
- 保存并展示真实 `reason_code`、执行状态和证据状态，避免统一显示为笼统的工作流失败。
- 为页面预留固定滚动条空间，消除不同页面高度下顶部菜单的横向跳动。
- 前端资源版本更新为 `20260825-5`，避免浏览器继续使用旧缓存。

## 影响与提升

- 影响范围：测试历史落盘、历史详情、日志下载、单用例/批次异常结束路径、全局页面布局。
- 不改变 W30/579 的动作协议、设备控制链、截图链、用例数据和执行门禁。
- 失败后可以直接从平台查看原始错误，不再只能依赖结构化步骤或本机任务状态。
- 执行尚未进入 Runner 时发生的异常也可追溯，不再出现“任务失败但没有用例历史”。
- 新旧记录共用同一查看入口；每路日志最多保留末尾 20 万字符，避免记录无限增长。

## 验收结果

- 自动化回归：`818 passed, 17 skipped, 9812 subtests passed`。
- 覆盖普通历史落盘、原始日志接口、单用例预检失败、未捕获异常和批次准备失败兜底归档。
- 实际浏览器验证旧失败记录：成功展示 813 字符 `stderr`，3 个日志下载入口存在并可触发下载。
- 浏览器控制台错误为 0；`git diff --check` 通过。
- 当前服务已用新代码运行在 `http://127.0.0.1:8765`。
