# Requirements

## Goals

- 在一级导航中新增位于“用例管理”前面的“PRD 转用例”。
- 上传 PRD 后按内置小周 QA Skill 生成结构化测试用例与 Excel。
- 生成后的全部用例必须在页面可视化展示并提供给对应人员审查。
- 审查通过且准出为 GO 后，可直接同步到现有用例管理。
- 提供独立验收报告和可核验产物哈希。

## Users And Scenarios

- 用例设计人员上传 PRD、查看生成进度、处理待确认并下载 Excel。
- 审查人员在线筛选、逐条查看、提出问题、退回修改或审查通过。
- 用例管理员预览同步变化并将已通过用例同步到目标项目。

## Acceptance Criteria

- 导航顺序为“项目总览 → PRD 转用例 → 用例管理 → 自动化执行……”。
- 支持 `.docx`、`.md`、`.txt`；不可解析输入给出明确错误，PDF/扫描件列为后续增强。
- 生成任务持久化且可查询；运行中的请求不承诺跨进程断点续跑。
- 生成产物包含 Excel、执行画像、审查快照及哈希；共享 Skill 保持只读。
- 审查页面展示固定层级、完整执行字段、关键词筛选、意见、退回和通过操作。
- 审查快照来自最终 Excel 回读，审查决定绑定 Excel SHA-256 和稳定 ID。
- 任一源数据或 Excel 变化使旧审查、准出和同步资格失效。
- 仅 `APPROVED + GO` 可以同步；同步使用事务、幂等和写入后读回校验。
- 同步后保留功能点、稳定 ID、来源任务、审查信息和 Excel 哈希；自动化状态为 `UNMAPPED`。
- 原有路由、Excel 导入、用例管理、执行和报告功能通过回归。
- 源码测试、API 测试、前端静态验收、真实 Excel 回读、同步读回及 Windows 便携版验证均进入验收报告。

## Constraints

- 运行时不能依赖用户安装系统 Python，也不能依赖原始 D 盘 ZIP 路径。
- QA Skill 必须版本化、校验哈希、只读使用；客户 PRD 和生成数据写在 Skill 外部。
- 当前 HTTP 服务只允许 loopback；首版审查人以姓名/工号留痕，不宣称远程身份认证。
- 不用用例数量代替质量；固定层级、四项 P0 复核、稳定 ID 和最终哈希绑定不得绕过；完整严格准出列为后续增强。

## Open Questions

- 无阻断问题。跨电脑审查、人员账号与严格多上下文评审按设计列为后续增强，不阻塞本次本机闭环。
